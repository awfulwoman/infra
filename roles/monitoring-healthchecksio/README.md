# Monitoring Healthchecks.io

This role registers a host with [Healthchecks.io](https://healthchecks.io). It sends a success ping during each playbook run, which gives dead-man's-switch monitoring for infrastructure automation.

The role creates the check, or confirms that it exists, through the Healthchecks.io API. It tags the check with the host type and inventory name, for easy filtering. The role then sends a success ping to confirm that the playbook ran. If the check stops receiving pings, for example because a host is down or Ansible stops running, Healthchecks.io sends an alert.

## Key Variables

| Variable | Default | Description |
|---|---|---|
| `monitoring_healthchecksio` | `true` | Enable the role |
| `monitoring_healthchecksio_name` | `{{ inventory_hostname }} - Core Playbook` | Name of the check in Healthchecks.io |
| `monitoring_healthchecksio_debug` | `false` | Print API response details |
| `vault_healthchecks_rw_apikey` | _(required)_ | Read-write API key from Healthchecks.io, stored in Ansible Vault |

## Design Notes

- The check schedule is hardcoded to `0 8 * * *` (daily at 08:00 UTC), matching the expected frequency of the `automation-infra` playbook runs.
- Checks are matched by name (`unique: ["name"]`) so re-running the role does not create duplicate checks.
- A `rescue` wraps the entire block. If the `community.healthchecksio` collection is not installed, the rescue handles this silently and the playbook continues, rather than failing. This makes the role safe to include everywhere, without the collection on every control node.
- Tags (`autogenerated`, host type, hostname) make it easy to group and filter checks in the Healthchecks.io dashboard.
